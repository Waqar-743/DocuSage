DocuSage 2.0.2 fixes the built-in `llama-server` Local AI runtime installer on Windows and ensures downloaded GGUF models start automatically after installation.

### Local AI Runtime Installer Fixes

- **Fixed Upstream `llama.cpp` v1.0+ Release Resolution:** Upstream `ggml-org/llama.cpp` `v1.0.0` moved prebuilt binaries to `bNNNNN` prereleases referenced by `nightly-tag.txt`. DocuSage now resolves `/releases/latest`, follows `nightly-tag.txt` to its pinned build tag, and scans recent non-draft `bNNNNN` releases so `windows-x86_64 (vulkan)` and other platforms always find valid prebuilt archives.
- **Automatic Windows x64 CPU Fallback:** Added fallback matching to compatible Windows x64 CPU builds (`bin-win-cpu-x64.zip`, `avx2`, `avx`, `noavx`, `openblas`, `bin-win-x64.zip`) whenever a Vulkan archive is unavailable, plus automatic `--n-gpu-layers 0` CPU retry if Vulkan driver initialization fails at startup.
- **Auto-Start Downloaded GGUF Models & Clean Error Handling:** Clicking **Install Local Runtime** now downloads, verifies, extracts `llama-server`, cleans stale binaries, and automatically starts an already-downloaded chat GGUF model (such as `Llama-3.2-1B-Instruct-Q4_K_M.gguf`) so offline chat works immediately. Install failures now clear the `resolving: 0%` progress bar and surface clear inline diagnostics.
