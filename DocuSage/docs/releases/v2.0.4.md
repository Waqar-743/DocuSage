DocuSage 2.0.4 isolates local GGUF inference in a supervised worker process so native `llama.cpp` faults can never terminate the desktop UI, fixes Windows portable CPU compilation flags, and hardens local model loading on 8 GB RAM machines.

### Crash-Isolated Local GGUF Worker & Diagnostics

- **Supervised Worker Process (`--local-engine-worker`):** Native `llama.cpp` model loading and generation now execute inside a crash-isolated child worker process spawned from `docusage.exe` with `CREATE_NO_WINDOW`. Native faults (such as Windows `0xc0000005` or `0xc000001d`) terminate only the worker while keeping DocuSage open with the exact exit code, last FFI step, and automatic no-mmap fallback retry.
- **Flush-on-Write Engine Log (`local-engine.log`):** Every native stage (GGUF header validation, backend init, model load, context creation, prompt decode, and first token decode) is flushed and `fsync`ed to `<app_data_dir>/logs/local-engine.log`, with the diagnostic log path shown directly in Settings.
- **Portable Windows x86_64 Build Flags:** Disabled host-assumed `GGML_AVX2` / `GGML_AVX` / `GGML_BMI2` / `GGML_FMA` / `GGML_F16C` / `GGML_SSE42` and `GGML_CPU_REPACK` in Windows release builds to eliminate illegal-instruction faults and reduce peak anonymous RAM usage on 8 GB RAM systems.
- **Verified Live Windows GGUF Self-Test:** Added `docusage.exe --local-engine-selftest <model.gguf>` and wired Windows CI to load `qwen2.5-1.5b-instruct-q4_k_m.gguf`, generate a real completion, and verify graceful rejection of corrupted GGUF files before publishing installers.

### UI Reliability, Concurrency Guards & Download Resume

- **Single-Flight Local AI Controls & Honest Status:** Disabled conflicting `Load Chat`, `Test Local Model`, `Reload`, `Unload`, and model-dropdown actions while loading or testing is active, and updated the Settings status badge to reflect true runtime state (`Model Loaded`, `Loading Model…`, `Testing Model…`, `Load Failed`, or `Standby`).
- **Resumable Partial Downloads & Focus Guard:** Persists and surfaces saved `.part` downloads on reopen with `Resume` / `Discard` actions, keeps Spotlight visible during active downloads and model loads, and wraps the desktop workspace in a React `ErrorBoundary`.
