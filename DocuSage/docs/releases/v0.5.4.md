DocuSage 0.5.4 improves PDF conversation reliability, model management, and the accuracy of the product website. It retains the existing desktop architecture and product identity.

### Desktop fixes

- Keep replies in the conversation that started them when switching chats. Block duplicate sends and recover cleanly from cancelled or failed requests.
- Restrict PDF answers to the selected document. Remove deleted documents from search, replace re-imported content without duplicate passages, and preserve the document's conversation.
- Restore the actual document index on startup and persist validated retrieval settings. Handle Unicode text and chunk overlap correctly.
- Clean up interrupted downloads, reject invalid GGUF files, discover downloaded models on restart, and preserve the selected model when restarting the AI engine.
- Enable native credential-storage backends, send Gemini credentials in headers, and apply remote Ollama authentication. Improve provider validation and error reporting.
- Fix desktop styles missing in the production build. Improve keyboard access, Settings focus, theme-aware controls, shortcut validation, and fallback window access.
- Check the actual GitHub release version from the update action. Updates still require downloading and installing a release.

### Website and visuals

- Describe the real text-PDF workflow, initial model downloads, optional cloud data sharing, and current limitations.
- Replace product pictures with five actual production Linux app captures, with separate cartoon illustrations for storytelling.
- Improve mobile layouts, accessibility, image loading, and copy. Remove about 17.5 MB of superseded public images.

### Download and first use

Choose either the Windows x64 `-setup.exe` or `.msi` installer below. Open DocuSage, then press `Alt+Space` or use the tray icon to show its window. Change the shortcut in Settings if another application reserves it. Connect a GGUF model or configure an optional provider. Local embedding and language models require initial downloads; model files are not included in the installers.

Use text-based PDFs. Scanned/image-only files need OCR before import. Cloud providers receive your prompt, supplied chat history, and retrieved excerpts. Answers and generated citations can be incorrect; inspect the retrieved context and original PDF.

### Verification and limits

The release workflow builds both Windows installer formats, runs the frontend and Rust regression suites, installs both packages, and checks installed startup, single-instance behavior, and a visible native window **before publishing**. `SHA256SUMS.txt` records the uploaded installer hashes.

The detailed Linux production audit passed 22 native integration checks, four final-build startup checks, and four additional UI/clipboard/theme/shortcut checks. Nine React regressions, ten Rust regressions, and six production website browser tests passed. Actual local Qwen 2.5 0.5B inference, PDF parsing, embeddings, persistent search, and credential storage were exercised. See the [audit report](https://github.com/Waqar-743/DocuSage/blob/v0.5.4/DocuSage/docs/audit.md) for evidence and reproduction commands.

Windows installer checks do not certify Windows inference or every UI interaction. The screenshots are from Linux. macOS, Wayland, multiple monitors, GPU acceleration, very large PDF collections, and the other model-catalog variants need separate testing. Remote adapters were tested with local protocol fixtures; paid provider accounts and hosted-model quality were not tested.
