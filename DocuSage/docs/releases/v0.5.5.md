DocuSage 0.5.5 introduces a redesigned desktop shell focused on faster onboarding, simpler navigation, and smaller downloads. The desktop architecture and product identity are unchanged.

### Refreshed desktop shell

- Consolidated primary navigation into a horizontal bar that starts at the center of the window and extends right. Chat, Documents, and AI Setup are one click away; every remaining page (Model Catalog, Downloaded Models, AI Providers, Appearance, Shortcuts, RAG Tuning, Advanced, New chat, Ingest PDF) moved behind a three-dot overflow menu.
- Simplified provider onboarding into a new Quick Setup tab. Paste one API key, press Test & Save, and DocuSage saves, tests, and activates the provider in a single step with immediate success or failure feedback. Model and base-URL overrides live in an optional advanced disclosure.
- Polished the chat experience: suggestion chips on the empty screen, avatar-led message bubbles, error-aware assistant avatar, and an input hint row documenting Enter and Shift+Enter behavior.
- Made the sidebar collapse state clearer with dedicated panel-collapse and rail-expand controls; the collapsed rail exposes Chats, Docs, and the expand toggle.

### Smaller installers

- Release builds now use single-codegen-unit thin LTO with stripped debug symbols and abort-on-panic, reducing a large share of binary weight carried into both installer formats.
- Windows packaging produces only the two shipped formats: the NSIS `-setup.exe` and the WiX `.msi`. NSIS packages use maximum LZMA compression and install for the current user; the WebView2 bootstrapper is downloaded during setup instead of being embedded.
- The production web build is minified JavaScript and CSS without source maps.

### Testing

- `npm run test:web` now starts a production preview server automatically, so website browser tests and accessibility audits run standalone instead of requiring a manually started dev server. All six website checks pass again without application changes.
- Nine React regression tests pass, and TypeScript checks remain clean.

### Download and first use

Choose either the Windows x64 `-setup.exe` or `.msi` installer below. Open DocuSage, then press `Alt+Space` or use the tray icon to show its window. Use AI Setup to paste a provider key, or connect a downloaded GGUF model. Local embedding and language models require initial downloads; model files are not included in the installers.

Use text-based PDFs. Scanned/image-only files need OCR before import. Cloud providers receive your prompt, supplied chat history, and retrieved excerpts. Answers and generated citations can be incorrect; inspect the retrieved context and original PDF.

### Verification and limits

The release workflow builds both Windows installer formats, runs the frontend and Rust regression suites, installs both packages, and checks installed startup, single-instance behavior, and a visible native window **before publishing**. `SHA256SUMS.txt` records the uploaded installer hashes.

Windows installer checks do not certify Windows inference or every UI interaction. Real `opt-level = 3` code generation is preserved so local inference speed is unaffected by the size reductions. macOS, Wayland, GPU acceleration, very large PDF collections, and the other model-catalog variants need separate testing. Remote adapters were tested with local protocol fixtures; paid provider accounts and hosted-model quality were not tested.
