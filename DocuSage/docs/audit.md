# Website and desktop audit

Audit date: 14 October 2026. The existing React/Tauri/Rust architecture is retained.
The detailed functional audit uses a production Linux build. Windows packaging
and installed startup are checked separately by the release workflow; its actual
status is recorded in GitHub Actions and the release notes.

## Scope and evidence

The public website and native desktop interface share Vite, but load separate
React bundles. Native functionality lives in `commands.rs`, `rag.rs`,
`providers.rs`, and `assistant.rs`; a browser UI preview cannot verify it.

The native harness runs a production binary through Tauri WebDriver in an
isolated Linux X11 session. It uses synthetic PDFs, the catalog's Qwen 2.5 0.5B
Q4_K_M model, actual ONNX embeddings, actual LanceDB storage, and a test keyring.
Remote-provider adapters use local HTTP protocol fixtures, not paid accounts.

Final machine-readable native results and original screenshots are in
[evidence](evidence/). Only a run with `completed: true` and all checks passing
constitutes a completed native test run. Intermediate results are not a release
certification.

## Website claims and their implementation

| Website statement | Implementation and verification boundary |
| --- | --- |
| Questions about a selected text-based PDF | `ingest_document`, filtered `query_similar`, `chat_rag`, `chat_cloud_rag`. Two PDFs with conflicting opening times exercise source isolation. |
| Local parsing, embeddings, and search | `pdf-extract`, fastembed BGE Small EN v1.5, persistent LanceDB. The embedding model must download initially. |
| Offline GGUF answers | `mistralrs` model loading and streamed general/document chat. Model files must download first. Hardware affects speed and quality; the full catalog is not certified. |
| Optional AI providers | Nine remote adapter variants are tested against protocol fixtures. Live OpenAI, Gemini, Anthropic, OpenRouter, Ollama, and LM Studio accounts/servers are not tested. |
| Cloud privacy boundary | Provider requests include the prompt, supplied conversation history, and selected excerpts. Original PDFs and the index are not uploaded by the RAG pipeline. History can include excerpts shown in earlier replies. |
| Protected credentials | Explicit native keyring backends for Windows/macOS/Linux; a fresh Linux Secret Service read is tested. No plaintext fallback. Availability depends on the host credential service. |
| Hidden launch and global shortcut | Native launch, shortcut registration, show/hide, Escape, single-instance behavior, and compact/medium/full modes. X11 behavior does not establish Wayland/Windows/macOS behavior. |
| Model catalog and controls | Streaming downloads, validation, complete/partial-file handling, catalog enumeration, deletion protection, connect/disconnect/restart. |
| Conversations, drafts, and themes | React local storage and native model/index restoration. Session ownership, stale selections, interrupted replies, reset failures, and re-import behavior have targeted regression coverage. |
| Retrieved context | Displays excerpts actually supplied to the model. Filename citations are generated by the model and can be wrong. There is no page-linked citation viewer. |
| Windows downloads | Links to GitHub Releases. Screenshots and detailed functional tests use Linux. Release automation separately checks both Windows installer formats before publishing. |

Copy now describes text PDFs, initial model downloads, local streaming versus
complete cloud replies, and the exact cloud data boundary. It explicitly states
that OCR, Word import, and an embedded PDF reader are absent. It removes claims
of guaranteed answers, fabricated research anecdotes, and unsupported license
status. No license is selected on the maintainer's behalf.

## Desktop corrections

- Requests keep their originating conversation while the user switches chats.
  Duplicate sends are blocked, and failed/cancelled requests release their slot.
- RAG searches the selected PDF rather than the whole collection. Both local
  and remote RAG can show the same actual retrieved context.
- Document removal deletes its indexed chunks; re-import replaces existing
  chunks transactionally and preserves other documents. SQL filters safely
  handle apostrophes. Windows canonical/picker paths identify the same document
  and retain its conversation on re-import.
- The UI restores documents from the actual index and prevents questions about
  stale/failed entries. Import selects the document tab.
- Chunking handles Unicode, extreme overlap, empty text, and the final passage
  without overflowing the configured character budget. Query logging avoids
  unsafe byte slicing of Unicode prompts.
- RAG settings validate, persist to disk, and load on restart. Reset failures
  are reported instead of displaying a success message.
- Local/cloud cancellation wakes waiting requests. Engine restart waits for
  cancellation, blocks overlapping requests, and preserves the selected file.
- Startup loads at most one discovered GGUF model. App-data downloads are
  rediscovered; partial downloads never appear as usable models. Failed download
  attempts clean up partial files and reject non-GGUF responses/path traversal.
  Startup also clears app-created partials left by a forced process exit.
- Platform keyring features are enabled explicitly. Gemini keys use a header
  rather than the URL; remote Ollama receives configured authentication.
  Provider error messages avoid echoing raw service responses. Disabled
  profiles cannot become active; endpoints and the reserved Local profile are
  validated. The Local connection check reflects an actually connected model.
- The update action checks the existing GitHub release and reports versions;
  it does not install updates automatically.
- Shortcut parsing rejects ambiguous/unmodified bindings. A failed startup
  binding falls back where possible; the window stays accessible when both fail.
- Settings have a dialog name, focus handling, and keyboard dismissal. Escape
  closes Settings before hiding the assistant. Native select painting follows
  the chosen theme. Browser previews are explicitly labeled simulations.
  Document/chat deletion uses named keyboard-operable buttons rather than
  clickable spans nested inside selection buttons.
- Separate lazy import loaders preserve each interface's CSS preload list.
  The production audit caught Vite attaching the website CSS to the desktop
  branch of a conditional import; native tests now assert the actual stylesheet
  is applied before testing features or capturing images.
- Rust/Arrow and lockfile compatibility are corrected; unused desktop bridge
  permissions and the obsolete Gemini-only command are removed. Windows build
  workflows use Node 22 and gate packaging on frontend checks.

## Visuals and performance

The five website product views are exported from native WebDriver captures:
light/dark PDF conversation, model catalog, provider settings, and shortcut
settings. The answers are produced by the actual GGUF model using a synthetic
field-guide PDF. There are no fabricated messages in these captures.

PNG originals remain under `docs/evidence`; WebP copies under `public/media`
preserve the captured interface without retouching. Cartoon research/privacy
guides and the existing mascot illustrations support the story, separately from
product evidence. Artwork is compressed to transparent WebP, image dimensions
reserve layout space, and secondary images load lazily. Twenty-two superseded
PNG assets totaling 17,524,690 bytes were removed from the public bundle.

## Reproduce the checks

Frontend (Node 22.22.2+ or 24.15+, matching the test dependencies):

```bash
cd DocuSage
npm ci
npm test
npm run build
npx playwright install --with-deps chromium
npm run preview -- --host 127.0.0.1 --port 1420
# In another terminal, from the same directory:
npm run test:web
```

The Pages workflow builds with `VITE_BASE=/DocuSage/` and runs browser checks
against that production base path before publishing. Playwright checks images,
anchor targets, console errors, horizontal overflow, theme switching, FAQ,
mobile navigation, and automated WCAG A/AA rules through axe.
When checking the `/DocuSage/` deployment locally, set `VITE_BASE=/DocuSage/`
for both the build and preview commands so Vite serves the same path.

Native Linux prerequisites include Rust, a C/C++ compiler, CMake, Protobuf,
GTK 3/WebKitGTK 4.1 development libraries, OpenSSL, D-Bus, Xvfb, Openbox,
xdotool, xsel, GNOME Keyring, WebKitWebDriver, ImageMagick, and `tauri-driver`.
Keep the model files outside the repository.

```bash
cd DocuSage
npm run tauri build -- --no-bundle
cd src-tauri
cargo test --release --lib
cd ..
# MODEL_PATH must contain the catalog's qwen2.5-0.5b-instruct-q4_k_m.gguf.
DOCUSAGE_BINARY="$PWD/src-tauri/target/release/docusage" \
MODEL_PATH=/path/to/test-models TAURI_DRIVER=/path/to/tauri-driver \
dbus-run-session -- bash tests/run-native-session.sh
# Supplementary UI, clipboard, themes, drafts, and shortcut checks:
NATIVE_TEST_SCRIPT=tests/native-ui.mjs \
DOCUSAGE_BINARY="$PWD/src-tauri/target/release/docusage" \
MODEL_PATH=/path/to/test-models TAURI_DRIVER=/path/to/tauri-driver \
dbus-run-session -- bash tests/run-native-session.sh
```

The harness creates a fresh temporary app profile by default. Set
`NATIVE_TEST_DIR` only to an isolated test directory: fixtures create/delete
documents, providers, and a model-download copy. The headless WebKit sandbox
override is scoped to this test script; production startup does not set it.

## Remaining limitations

- Windows inference and the complete Windows UI are not verified by the Linux
  suite. The Windows release workflow checks package installation, startup,
  single-instance behavior, and window visibility. macOS packaging, multiple
  monitors, fractional DPI, Wayland, and interactive tray menus need separate
  platform-specific testing.
- Paid providers are protocol-tested with synthetic responses, not live keys.
  Hosted model availability, service quotas, and answer quality are not verified.
- Only the compact Qwen model is used for inference here. Other catalog models,
  GPU acceleration, encrypted/complex PDFs, and very large document collections
  require separate compatibility/performance testing.
- Image-only PDFs require external OCR. Cloud answers arrive when complete;
  cloud token streaming and an automatic installer/updater are absent.
- AI answers and filename citations remain fallible. Retrieved context helps
  inspect evidence but cannot guarantee a correct answer.
- The repository has no license file; source availability does not establish
  an open-source license grant.

[Website measurements](evidence/website-results.json) record no broken images or
horizontal overflow. The complete page requested about 547 KB in the local
preview, with observed layout-shift scores of 0.011 on desktop and 0.039 on mobile.
These are local browser measurements, not a public network-speed benchmark.
The complete production web directory is approximately 0.9 MB after cleanup.

Original native captures, desktop/mobile website captures, and the actual local
RAG answer are retained under `docs/evidence`. The native suite includes a real
GTK PDF picker interaction and reloads the application to verify persisted chat.
Remote responses remain protocol fixtures, as explicitly marked in its results.

The [Windows verification workflow](../../.github/workflows/verify-desktop.yml)
builds the production executable, runs the Rust/frontend regressions, and checks
that the executable remains running after native startup. It does not publish an
installer or certify interactive Windows UI behavior. The Pages workflow runs
the browser checks before publishing the website. Their runs are visible in
[GitHub Actions](https://github.com/Waqar-743/DocuSage/actions).

The [release workflow](../../.github/workflows/build-release.yml) additionally
builds, installs, and launches both NSIS and MSI packages before publishing the
tagged version. It retains installation results as an Actions artifact and
attaches installer SHA-256 checksums to the release. This is package/startup
verification, not a Windows inference or full UI certification.
